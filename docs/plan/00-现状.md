## 2. 建议链现状

### 2.1 调用链

```
ui._update → advisor.snapshot(st)
             ├─ _predict → infer.DeckPredictor.predict
             ├─ board_from_state(st) 把日志状态翻译成 model.Board
             └─ _advice → policy.plan_turn(board, cards, aoe_risk=…, weights=…, side=0)
                          → policy.advice_lines()
ui._maybe_ai：发现/抉择由 policy.pick_choice 直接决定（不调 AI，ui.py:728-745）；
             逐回合 AI 路线默认关闭（ui.py:749-752）。
```

- `advisor._advice()` 只在「轮到我方」时给建议，否则直接返回空
  （`hsai/advisor.py:441-454`）；`side` 固定 0，因为 `board_from_state` 永远把
  我方放在 0（`advisor.py:139-155`）。
- `state.snapshot()` 的 `is_our_turn` 用 `turn_owner`（`state.py:1205`），
  而 advisor 用 `effective_turn_owner()`（`advisor.py:318`）——两处口径不同。

### 2.2 plan_turn 的评分口径

1. 局面分：`model.evaluate(board, weights, aoe_risk, perspective)`
   （`hsai/model.py:758-820`），默认权重见 `model.py:669-677`：
   `tempo 1.0 / face 0.9 / hand 0.7 / health 0.55 / taunt 0.8 / aoe_risk 1.2 / fatigue 0.6`。
   组成：随从价值差、相邻光环、打脸进度×0.5、手牌资源×1.2、
   血量护甲×0.35、嘲讽阻断×-0.4、疲劳、AOE 暴露扣分；
   对方已死 +10000，我方已死 -10000；对方总攻 ≥ 我血+甲时 -420
   （`lethal_bonus` 不在默认权重里，用 `.get(...,1.0)` 恒为 1，`:816-819`）。
2. 每步贪心：枚举 `legal_actions`（`policy.py:122-276`），跳过 `end`，
   先用 `_mode_allows` 过滤攻击（`:1297-1347`），再 `apply_action` 模拟、
   `evaluate` 打分（`:743-789`）。
   - 打死对方 +5000；`raw <= 0.01` 视为无效动作跳过；
   - `gain = raw + PRIORITY_BONUS[categorize]`，优先级表见 `policy.py:37-45`：
     `lethal 1000 / free_trade 6 / board 3 / draw 1.6 / discover 1.0 / defend 0.6 / other 0`；
   - 抽牌额外每张 +1.2（`:760-765`）；
   - 解场模式下「能杀且能活」的交换再按目标威胁 ×0.6 加权（`:766-780`）；
   - 攻击并列时减去攻击者自身威胁 ×1e-3，优先用便宜的换（`:781-785`）；
   - **接受阈值 `EPS = 0.35`**（`:33`），最多 `MAX_STEPS = 6` 步（`:75`）。
3. 无收益但手里有能打的牌时，先打费用最低的一张兜底（`:790-803`）；
   剩余法力且有「预备」牌时追加一条预备建议（`:812-824`）。
4. 备选：对开局每个合法首手，递归 `plan_turn(steps=2)`，收益 >0.01 才收，
   按收益降序取 3 条（`:832-852`）。
5. UI 分数：`_score_from_gain = 55 + 9*ln(1+gain)`，夹在 1..97，gain≥100 记 99
   （`policy.py:902-905`）。
6. 自对弈走的是另一个入口 `policy.best_action`（`policy.py:541-567`），
   接受阈值是 **0.25**（`min_gain`），和 plan_turn 的 0.35 不是同一套口径。
   `hsai/sim/engine.py:69-75` 的 `greedy_agent` 是它唯一的生产调用方。

### 2.3 斩杀

- `max_face_damage()`（`policy.py:572-633`）：
  - 随从攻击段按风怒拆成 1/2 段，再逐个分配去撞嘲讽，溢出伤害不转脸；
  - 手牌直伤按费用升序吃法力累加；
  - 英雄技能直伤；
  - `total >= 敌方血量+护甲` 判 `lethal`。
  - **缺口**：只算一次武器攻击、不含英雄自身 `hero_atk`、不含场上法伤
    `spell_damage`（对比 `apply_action` 的 `policy.py:516` 会加法伤），
    也不含英雄风怒的第二下 —— 这些都会让斩杀被低估。
- `_lethal_sequence()`（`policy.py:668-703`）：确认理论可斩后，按
  「打脸伤害×10 + 移除嘲讽×4 + 击杀 +1000」贪心拼最多 12 步，
  拼不出击杀就返回 `None`，不用假路线。
- `plan_turn` 拿到 `_lethal_sequence` 就整条返回，`gain=999`（`:724-739`）；
  理论够但拼不出线路时把 `lethal` 降级为 False 并给 note（`:826-830`）。

### 2.4 抢血 / 解场判定

- `race_plan()`（`policy.py:1248-1284`）：
  - 我方每回合伤害 = 场面攻击（风怒按两下）+ 武器攻击 + 英雄技能直伤；
  - 手牌爆发 `_hand_burst` 从对手血量里预先扣掉；
  - 对手每回合伤害 = 对手场面攻击 + `手牌数 × opp_coeff`；
  - 比较「我几回合赢 / 他几回合赢」，我更快 → `race`，否则 `trade`。
  - **`opp_coeff` 固定 1.5**：`advisor` 调 `plan_turn` 没传该参数
    （`advisor.py:456-462`），`aggression_coefficient()`（`policy.py:1213-1227`）
    在生产代码里**没有调用方，只有 tests/test_race.py 用**。也就是说对手是快攻
    还是控制，当前不影响抢血/解场判断。
- `_mode_allows()`（`policy.py:1297-1347`）：
  - `race`：只有「白吃且打完仍更快」才允许交换；非白吃只有在目标攻击力
    ≥ 我当前血量（不换就死）时才允许；打脸始终允许。
  - `trade`：只要有划算交换（`_has_profitable_trade`，`:1350-1363`，
    用 `unit_threat` 净值复核），就不打脸；换随从要按 `board_threat`
    的双方差值 >0 才换。
- `unit_threat`/`board_threat`（`:1391-1445`）是交换价值的统一口径。

### 2.5 发现 / 抉择打分：`score_choice` / `pick_choice`

- `pick_choice()`（`policy.py:1165-1206`）：选项里若 ≥2 个克苏恩技能，
  走规则化 `_cthun_choice`；否则每项查卡、`parse_effect`、`score_choice`，
  按分数降序，返回 `(下标, 理由, 与第二名分差)`。认不出的牌固定 -9。
- `score_choice()`（`policy.py:1012-1114`）六层叠加：
  1. 当回合可打 +2 / 不可打 -2；
  2. 立即收益：可击杀随从 `3*n + 最痛攻击×0.3`、硬解 +3、过牌 1.8/张、
     回血 +0.8、护甲 +0.7、召唤按身材×0.7（嘲讽×1.2）、加费 +1.2、
     buff 按「每只收益 × 最多 2 只」×0.6；随从再按 `(攻+血)/费用` 加最多 2.5；
     `tripled` 对伤害/召唤/buff 乘 3；
  3. 卡组主题（法伤/快攻/随从）；
  4. 场上法伤加成；
  5. 手牌法术数与法伤随从的配合；
  6. 对手形态（快攻偏解场/回血，控制偏大身材/过牌）。
- **已发现的打分缺陷**：第 6 层的条件写作
  `if effect.damage or effect.destroy or effect.taunt if hasattr(effect, "taunt") else False:`
  （`policy.py:1104`）。条件表达式优先级使整句等价于
  `(damage or destroy or taunt) if effect有taunt属性 else False`，
  而 `Effect` 数据类没有 `taunt` 字段（`model.py` 的 `class Effect`），
  所以这一句**恒为 False**，快攻对局的「解场/回血加分」从未生效。
- 分差 `gap` 返回后 UI 没有使用（`ui.py:736-745` 只取 `idx/why`），
  「第一名和第二名咬得紧」这个信号目前浪费。
- 抉择（choose one）：`choose_one_branches()`（`policy.py:98-119`）按
  「抉择：…或者…」切分并逐段重解析，每个分支在 `legal_actions` 里生成独立动作
  （`:193-200`），`apply_action` 用分支文本替换卡面结算（`:435-442`）。
- 发现/抉择的执行入口：`ui._maybe_ai` 先看 `snap["choice"]`，直接调
  `pick_choice`，完全不走 AI（`ui.py:728-745`）；选项来自
  `state._on_choices()`（`state.py:811-859`）与 `advisor._choice_view()`
  （`advisor.py:543-563`）。

### 2.6 克苏恩四技能

- 技能名常量：`policy.CTHUN_SKILL_NAMES`（`policy.py:932`）。
- 结算：`apply_cthun_skill()`（`policy.py:935-978`）：
  愤怒 7 点分摊、领域前两个随从 +2/+3、凝视 5 点打最高攻并回血、仆从召 2 个 2/3 嘲讽；
  `tripled=True` 时数值 ×3。
- 规则化选择：`_cthun_choice()`（`policy.py:1117-1161`）按用户定的档位：
  抢血/对面 ≥3 随从 → 愤怒（1 档）；我方 ≥2 随从 → 领域（2 档）；
  缺血或对面有 ≥4 攻大怪 → 凝视（3 档）；其余 → 仆从（4 档）。
  同档优先「本局还没用过」的技能（`me.cthun_used`）。
- 选项已用过信息有两条来源：
  - `state.note_cthun_choice()`：选项里没出现 = 已用过（`state.py:1096-1108`）；
  - `state._on_choice_sent()`：提交选择时按 refs 记下选了哪个（`:798-809`）。
- 生成可执行动作：`legal_actions` 里有「帝国之眼在场 → 每回合 2 次技能」
  （`policy.py:162-175`）和「打出触发克苏恩技能的牌 → 四个技能各一个动作」
  （`:237-244`）；`apply_action` 分别结算（`:400-419`、`:443-446`）。
- **按实例计数只做了一半**：
  - `state.cthun_view()` 找到场上的 `BE_013` 后把 `key` 算出来，但**没有使用**，
    最终仍返回全局 `self.cthun_used`（`state.py:1110-1124`）；
  - `state.cthun_by_source` 只在 `reset()` 里赋值两次（`:166`、`:217`），
    **从未被读**；
  - `policy` 用的 `me._cthun_by_unit` 是动态属性，`SideState.clone()`
    （`model.py:414-434`）不复制它，跨 `apply_action` 会丢；
  - `policy.py:414` 的 `me._log_cthun` 全仓没有赋值点。
  结论：AGENTS 所说的「克苏恩按实例计数」在事件层只覆盖了
  `note_cthun_choice` 的全局集合，模拟层与面板层都没有真正按实例走。

## 3. 状态层现状

### 3.1 身份判定（谁是我方）

- 主判据：**只有我方的手牌有 `card_id`**。
  - `_track_visibility()`：第一次见到「带 card_id 的手牌实体」就锁定
    `our_id`（`state.py:898-906`，`_our_id_locked` 在 `reset()` 复位，`:174`）。
  - `_fix_our_id_by_name()`：当「一侧有可见手牌、另一侧为 0，且当前认定的我方
    一张都看不到」时翻面（`:666-692`）；一旦翻过就置 `_id_by_hand_done=True`。
- 名字绑定：`_bind_by_action()`（`:644-664`）、`_infer_first_player()`
  （`:620-642`，靠幸运币 `GAME_005` 或第 3 回合水晶数推先手）、
  `_bind_pending_names()`（`:694-713`）。
- `_on_entity` 明确不按 `GameAccountId` 判定我方（`:326-332`）。
- **跨局残留**：`_id_by_hand_done` 没有在 `reset()`（`:164-241`）里清零，
  全仓只有 `:687`、`:691` 两处出现。结果是同一进程的第二局起，
  按可见手牌翻面的兜底永远提前 return，只剩「首个可见手牌锁定」这一条路。

### 3.2 回合归属

- 回合数是 GameEntity(1) 上的 `TURN`，其他实体上的同名 tag 不采（`:486-496`）。
- `turn_owner` 来自 `CURRENT_PLAYER` 两种方言（GameEntity 数字 / 玩家实体布尔），
  并与「先手 + 回合奇偶」交叉校验，对不上就丢弃（`:497-531`）。
- `effective_turn_owner()` 在 tag 缺失时用 `first_player + turn 奇偶` 推
  （`:917-927`）；`can_attack` 也用它（`:1177`）。
- 在日志里 turn_owner 经常是 `None`，所以 advisor、`can_attack` 都用推断值；
  只有 `state.snapshot()` 还直接比 `turn_owner`（`:1205`）。

### 3.3 牌库数

- 日志里没有「剩余牌库」字段（AGENTS 已记录 `DECK_SIZE`/`CARD_COUNT` 为 0 次）。
- 实现：`our_drawn` 累加，两个来源：
  1. `NUM_CARDS_DRAWN_THIS_TURN` 每回合归零，按**段内最大值**累加
     （`state.py:536-549`）；
  2. 我方实体进出牌库的净变化（换牌回库、塞牌、从牌库拉出）反向调整
     （`:458-467`）。
- `Side.deck_count = max(0, 30 - our_drawn)` 在 `_side()` 里对**双方**都这样算
  （`:1037-1038`）。advisor 只修正我方：`deck_total = len(our_deck) or 30`，
  `snap["our"]["deck_count"] = max(0, deck_total - drawn)`（`advisor.py:308-311,338-340`）。
  因此：
  - 对手牌库数 = 30 − **我方**抽牌数，不是对手真实剩余；
  - 我方未登记 40 张卡组时，牌库数也会少算 10 张。
- 预判会用这个错值做分母：`deck_count=opp.deck_count if opp.deck_count else …`
  （`advisor.py:431`）。

### 3.4 墓地

- 记录：实体进 `ZONE_GRAVE` 时记 `(死亡回合, 全局递增序号)`
  （`state.py:449-451`），`grave_meta`。
- 视图：`_grave_view()` 用**卡面原始数值**（死掉的实体标签会被清零），
  带 `deathrattle` 标记、`dropped_turn`、`seq`（`:972-986`）。

## 4. 学习与反馈链路

### 4.1 数据流

```
对局结束
  advisor._record_result
    ├─ infer.retrospect(opp_class, revealed)      → RetroTruth（真值）
    ├─ advisor.observation_row(...) → data/observations.jsonl（schema 2）
    ├─ memory.record_opponent(...)  → data/opp_history.jsonl（只记 trusted）
    └─ learn.absorb_observations → 可能新增 learned_* 原型 → meta.save()
  advisor._finish_game
    └─ data/games.jsonl + data/last_review.json
ui._ai_review_worker（AI 可选）
    ├─ ai.review → memory.add_lessons → data/lessons.jsonl
    └─ 若有 👎：feedback_worker → data/advice_feedback.jsonl
```

### 4.2 observations 真值

- 一行 = 一局：`advisor.observation_row()`（`advisor.py:714-748`），
  `schema=2`；字段：`game_id/ts/our_class/opp_class/result/turns/opp_deck_left/`
  `opp_hand/revealed(带回合)/trace/pred_archetype/pred_confidence/truth/`
  `unexpected_cards/our_hand`。
- **预测与真值分开存**：`pred_*` 是当时猜测，`truth` 是局末回看。
  学习只吃真值（AGENTS 的「学习标签必须是真值」在此落地）。
- 真值：`retrospect()`（`infer.py:326-375`）用全部已见牌算覆盖率，
  排除「所有原型都不认识」的牌（偷来的牌/幸运币），
  兼容 `[[id,回合],…]` 与 `[id,…]` 两种 revealed（`:339-346`）。
- `RetroTruth.trusted`（`infer.py:119-129`）：
  `coverage ≥ 0.85`（`TRUST_COVERAGE`）且领先第二名 ≥ 0.08（`TRUST_GAP`）。
- 本机现状：`data/observations.jsonl` **178 行，全部 schema 2，
  存的 truth.trusted=true 的 150 局**；`observations.jsonl.bak` 里是更老的数据。
  （AGENTS 提到的「174 行 schema 1」已通过 `hsai learn --backfill` 处理，
  但其他机器/备份仍可能有老行。）

### 4.3 meta 存储：一原型一文件

- 目录 `data/meta/<id>.json`（`paths.META_DIR`，`paths.py:45`；
  `MetaDB.save` `meta.py:204-233`）。
- `save()`：先写内存里每个原型（id → 文件名，`_file_stem` `:151-153`），
  再删除目录里「不在内存中且能解析成原型」的 json（`:219-233`）。
  解析失败的文件保留，避免吞用户数据。
- 加载：`MetaDB.load` 自动识别目录/老单文件，并把老 `meta.json` 拆成目录、
  原文件改名 `.migrated`（`:243-273`）。
- 原型 id：`content_id()` 对标志牌集合算 md5 前 8 位（`:355-366`），
  id 跟内容走，不跟序号走。
- 文件内容：`cards: [{id,name,cost,count}]` 按费用升序（`as_dict` `:66-85`），
  方便人工核对；还存 `prior/prior_base/source/tags/note`。
- 命名：`pick_key_cards` + `key_card_rank`（`:312-352`），
  **稀有度硬优先 → 出牌率 → 费用/名称/id 兜底**；只取一张牌，撞名往后挪
  （`_name_archetype` `:369-386`）。用户/客户端给的名字优先
  （`deckcode.resolve(name=…)` `deckcode.py:180-206`）。
- 本机 `data/meta/` 当前 18 个 json。

### 4.4 先验校准、增量学习、重建

- 校准：`learn.calibrate_priors()`（`learn.py:114-157`）
  - 每行真值先经 `_row_truth()`（`:95-111`）：**有 revealed 就按当前原型库
    重算**，没有才退回读存下来的 `truth.arch`；

    没有 `prior_base` 时先钉住再覆盖 `prior`（`:151-155`）；

## 5. 已知限制清单（从 AGENTS.md「坑」提炼，附当前代码依据）

1. **身份只能看可见手牌**：`GameAccountId` 在练习模式会判反，代码已按此实现
   （`state.py:326-332,898-906`）；名字绑定依赖行为推断，日志缺行时会退化。
2. **牌库数只能靠抽牌反推**：没有剩余牌库字段；`30 - our_drawn` 是硬编码，
   40 张卡组要靠手动登记（`state.py:1037-1038`、`advisor.py:311`）。
3. **对手手牌只有张数，没有具体牌**：`_unknown_cards(opp.hand_count)`
   （`advisor.py:220`），所以「对面手上有什么」只能靠原型后验估计。
4. **真值/预测必须分离**：学习只吃 `truth.trusted`，否则先验自我确认
   （`infer.py:119-129`、`learn.py:114-157`）。老 schema 1 数据要回填。
5. **`retrospect()` 必须同时吃 list/tuple 两种 revealed**：JSON 读出来是
   list（`infer.py:339-346`），只判 tuple 会 `TypeError`。
6. **校准必须从 `prior_base` 出发**：否则同一条命令跑几遍会把先验洗成观测频率
   （`learn.py:144-155`）。
7. **一个原型一个文件**：`save()` 会删掉「不在内存且能解析」的文件；
   手改坏的文件保留（`meta.py:204-233`）。
8. **原型 id 跟内容走**：`content_id()`（`meta.py:355-366`），
   否则增删同职业原型会让历史 `truth.arch` 全部错位。
9. **增量学习会冻结模板**：已有原型重合 ≥0.6 就跳过（`learn.py:390-392`），
   口径变了必须 `meta rebuild`，它不会自我更新。
10. **聚类算法有两个已知弱点**（暂未修）：单链聚类会「串味」；
    两个变体各占一半时模板会变成两套牌的并集（AGENTS 记录，代码见
    `meta.py:396+` 的单链实现，无平均连接/张数上限）。
11. **衍生物不算对手打出的牌**：采集端与读取端都要过滤
    （`state.py:772-780`、`meta.py:415-419`），否则原型会被撑到 40 张。
12. **命名规则是硬优先级**：稀有度 > 出牌率，且只取一张牌、不做拼接
    （`meta.py:312-386`）；用户给的名字不覆盖。
13. **先验表示「多常遇到」，不是胜率**：不要再用胜负调先验
    （AGENTS 记录已删的逻辑；当前 `record_opponent` 只记形态）。
14. **同一指标不能有两套算法**：`our_minions_played`（只算手牌打出）
    与 `sum(our_played)`（含召唤物）并存的历史问题
    （`state.py:187-210`，读取侧 `advisor.py:330` 用前者）。
15. **同名/重复定义会静默覆盖**：`state.py:288` 与 `:292` 两个
    `elif kind == "block_start"`，后者永远到不了；改完要数方法名。
16. **模块级函数没有 self**：`board_from_state()` 是模块级函数
    （`advisor.py:139`），要访问 Advisor 字段只能写在类方法里。
17. **`data/window.json` 键不能复用**：`collapsed` 与 `collapsed_sections`
    必须分开（`ui.py:135` 读 `collapsed_sections`）。
18. **测试要覆盖「只在一个分支里调用」的函数**：`include_ambient=False`
    会绕开环境探测分支（测试约定，`AGENTS.md`）。
19. **内置种子原型已删，不要加回**：无原型时返回「未知卡组 0%」是诚实降级
    （`infer.py:256,279-298`）。
20. **`ast.parse` 自检**：多次切片删除吞行；PowerShell heredoc 会吃 `$`/引号，
    改文件用 write/edit 工具（工程约定）。
