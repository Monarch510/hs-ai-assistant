# 04 学习链路可观测：calibrate / backfill / rebuild 不再静默「0 个原型」

> 优先级：P2（学习链路，在正确性任务之后）
> 规模：一条命令链两个文件（`hsai/learn.py` + `hsai/cli.py`），一个 AI 独立可完成
> 前置阅读：`docs/plan/00-现状.md` §4.2、§4.4、§5.6、§7 C11
> 基线：`Ran 160 tests … OK`

## 1. 目标

`python -m hsai meta calibrate` 必须打印「读了多少行、多少行可信、哪些行被剔除、每个职业样本数、每个原型的先验 before → after、因样本 <5 被跳过的原型及原因」，而不是只输出「修正 N 个原型」；`learn.calibrate_priors()` 返回结构化报告。

可验收：新增 `tests/test_learn_report.py` 全绿；`tests/test_learn.py` 除一处返回类型断言外不改动并通过；全量测试 OK；**先验口径、混合公式、`prior_base` 处理顺序全部不变**（同一条命令跑两遍结果一致）。

## 2. 背景

- **00 §4.4**：`learn.calibrate_priors()`（`learn.py:114-157`）只返回 `updated: int`。`cli.py:106-111` 打印「已按本地对局修正 N 个原型的先验」。
- **00 §4.2 / §5.6**：校准只吃 `truth.trusted`（150/178 局），同职业样本 <5 不校准，混合权重 `min(0.7, 总数/20)`，且必须从 `prior_base` 出发。这些口径**都是对的**，问题只是「不说的部分」：样本为什么被跳过、哪个原型改了多少，全看不到。
- **00 §7 C11**：明确把「给 `meta calibrate` / `backfill` / `rebuild` 补上样本数、剔除原因、前后先验」列为候选任务，目的就是避免「跑成功但什么都没改」和「改了很多但不知道改了啥」。
- **AGENTS 教训**：`observations.jsonl` 里 174 行 schema 1 没有 `truth` 字段时，`meta calibrate` 曾长期输出「修正 0 个原型」而不报错——同类静默问题不能再出现。

### 3.1 `learn.calibrate_priors()`（`learn.py:114-157`）

- 返回值从 `int` 改为 `dict[str, Any]`，字段固定为：
  ```python
  {
    "rows": 178,              # 读入的有效行数
    "no_class": 0,            # 没有 opp_class 被剔除
    "untrusted": 28,          # truth 不可信被剔除
    "trusted": 150,           # 进入统计的行数
    "updated": [              # 实际改动的原型
        {"id": "warrior_5d4ebb59", "name": "战士·斩杀",
         "before": 0.30, "after": 0.41, "samples": 22, "weight": 0.70},
    ],
    "skipped": [              # 本职业样本 <5 被跳过的原型（同职业多个时逐个列）
        {"id": "warrior_a1b2c3d4", "name": "战士·控制", "class": "WARRIOR",
         "samples": 3, "reason": "本职业可信样本 3 < 5"},
    ],
    "total_rows": 178,        # 文件里的行数（含坏行）
  }
  ```
- 顺序与算法**一个字都不许改**：先 `_row_truth()` 重算、只收 `trusted`、`prior_base` 为 `None` 时先钉住、`weight = min(0.7, total / 20)`、最后 `normalize_priors()`。
- 没有观测时返回 `{"rows": 0, ..., "updated": [], "skipped": []}`，不要抛异常。
- `learn.rebuild_learned()`（`412-431`）的返回里补一个 `"observations": <聚类用到的行数>`（`absorb_observations` 内部 `load_observations` 已经读过；不要为了拿行数重复读两遍——能顺手拿到就加，拿不到就保持原样并在报告里说明）。

### 3.2 `hsai/cli.py`

- 抽一个纯打印函数，测试可单独调用、不碰真实 `data/`：
  ```python
  def _print_calibrate_report(report: dict, meta_dir=None) -> None
  ```
  输出中文短句（与 `_rebuild()` 的风格一致），示例：
  ```
  读入 178 行：可信 150 行，无职业 0 行，真值不可信 28 行
  WARRIOR：可信 22 局
    warrior_5d4ebb59  战士·斩杀  先验 0.30 -> 0.41（样本 22，权重 0.70）
    warrior_a1b2c3d4  战士·控制  跳过：本职业可信样本 3 < 5
  修正 1 个原型（共 18 个）；没有观测数据的职业保持先验不变
  ```
  0 行 / 0 修正时也必须有一句原因（如「没有对局记录，先验不变」），不能只打「修正 0 个原型」。
- `cmd_meta` 的 `calibrate` 分支（`106-111`）改为：拿报告 → `meta.save()` → `_print_calibrate_report(report)`。**保存行为保持不变**（仍无条件 save）。
- `_rebuild()`（`119-136`）只加一行「聚类样本 N 行」（来自 3.1 的 `observations`），其余输出格式不动。
- 不要动 `cmd_learn` 的 backfill 输出（00 §4.4 已有），也不要动 `--dry-run` 语义。

### 5.2 `tests/test_learn_report.py` 至少覆盖

1. **样本数/剔除原因**：临时目录造 6 行（4 行可信、1 行无职业、1 行不可信）→ 报告 `total_rows=6`、`trusted=4`、`no_class=1`、`untrusted=1`。
2. **同职业样本 <5**：造 3 行可信 WARRIOR → 该职业所有原型进 `skipped`，`reason` 含 `< 5`，`updated == []`。
3. **before/after**：造 6 行可信、同一套牌 → 对应原型 `updated[0]["before"]` 等于校准前 `prior`、`after` 等于校准后 `prior`，且 `after != before`。
4. **幂等**：同一份数据连跑两次，第二次报告里的 `before` 等于第一次的 `after`（证明「从 prior_base 出发」没被改动）。
5. **空数据**：文件不存在 / 0 行 → 返回 `rows=0`，`updated=[]`，不抛异常。
6. **CLI 打印**：`cli._print_calibrate_report(report)` 的输出里含「可信」「跳过」「->」「没有对局记录」等关键字（用 `contextlib.redirect_stdout` 捕获；**不要调用 `cmd_meta`**，避免读写真实 `data/`）。
