> 优先级：P1（补测试，排在三个正确性任务之后）
> 规模：单模块（`hsai/model.py`），一个 AI 独立可完成
> 前置阅读：`docs/plan/00-现状.md` §1、§2.2、§5.14、§6
> 基线：`Ran 160 tests … OK`

## 1. 目标

用表驱动测试把「`Effect` 字段 → `parse_effect` 解析 → `apply_effect` 结算」三条腿钉住（新增至少 10 类效果用例），并清掉 `evaluate()` 里「权重键不在 `DEFAULT_WEIGHTS`、`.get(...,1.0)` 恒为 1」的僵尸读取。

可验收：新增 `tests/test_effects_model.py` 全绿；全量测试 OK；`DEFAULT_WEIGHTS` 仍是 7 个键、数值不变。

## 2. 背景

- **00 §1**：`hsai/model.py`（857 行）负责局面模型、`parse_effect`/`apply_effect`/`evaluate`、`DEFAULT_WEIGHTS`。它是建议链的地基：解析错一处，斩杀、评分、抢血全部跟着错，但**不会报错**。
- **00 §2.2**：`DEFAULT_WEIGHTS`（`model.py:669-677`）只有 `tempo/face/hand/health/taunt/aoe_risk/fatigue` 七个键；`evaluate()` 里却写着 `if w.get("lethal_bonus", 1.0):` 与 `score -= 420 * w.get("lethal_bonus", 1.0)`（`model.py:816-819`）。`lethal_bonus` 不在默认权重里、也没有任何权重文件提供它，所以这段**恒按 1.0 执行**：看起来像可调参数，实际调不了。
- **00 §5.14**：「同一个数别留两套算法」。`apply_effect` 的伤害结算加法伤（`model.py:608-631`），但 `parse_effect`/`evaluate` 里对同一张牌的解读没有测试锁住——改一处漏一处，面板不会报错。
- **AGENTS「改卡牌效果时」**：新增字段要同时改三处（`Effect` 数据类、`parse_effect` 赋值、`apply_effect` 结算、以及 `known` 判断）。这个约定目前**没有测试兜底**，靠人记。

本任务不是「重写规则库」：`parse_effect` 的文本规则不在本批范围内，只补测试 + 修测试能证明的结算缺陷。

### 3.1 `evaluate()`（`model.py:758-820`）—— 僵尸权重

- 把 `if w.get("lethal_bonus", 1.0):` 改成无条件判断（保留原来的防守阶跃）：
  ```python
  foe_reach = foe.board_attack + (foe.weapon.atk if foe.weapon else 0)
  if foe_reach >= me.hero_hp + me.armor:
      score -= 420
  ```
  注释保留原意：这个阶跃是「被对手斩杀线覆盖 → 开始防守」，不是「我能斩杀」的奖励（`00` §2.2 已解释为什么不能加斩杀奖励）。
- **不要**往 `DEFAULT_WEIGHTS` 里加 `lethal_bonus` 键（没有权重文件会提供它，加了只是把死键变成死默认值）；不要改其余 7 个权重数值。

### 3.2 `apply_effect()` / `parse_effect()`（`model.py:534-665` / 解析段）

- 已知一处必现缺陷：**`apply_effect()` 没有 `armor` 分支**。`armor` 只在亡语结算里被加（`model.py:499-500`），普通法术/英雄技能的 `Effect(armor=…)` 在 `apply_effect` 里被静默丢掉。加一条 `if eff.armor: caster.armor += eff.armor`，并用「加甲牌」用例锁住。
- 其他只修**测试能证明的**结算缺陷；修之前先用一条失败用例复现，再改代码。
- 允许改动范围：`apply_effect` 内部各分支、`Effect` 的默认值、`parse_effect` 里明显漏赋值/漏判断的行。
- 不允许：新增 `Effect` 字段、改 `parse_effect` 的整体规则结构、改 `Board`/`SideState`/`Unit` 的接口、改 `evaluate` 的权重公式（除 3.1）。
- 如果测试暴露的问题必须改**其它模块**才能修：**停下来**，把它写进交接物「发现但未修」，不要跨文件（具体例子见 6.3）。

### 3.3 `tests/test_effects_model.py`（新增）

用 `unittest` + 表驱动。每类效果两条断言：`parse_effect(card)` 解析出的字段 + `apply_effect(eff, caster, target)` 结算后的局面（`hero_hp`/`board`/`armor`/`hand` 张数/`frozen`）。不要碰网络、不要读 `data/`，卡牌对象用 `hsai.cards.load()` 里现成的卡，或 `dataclasses.replace` 改字段。

### 5.2 `tests/test_effects_model.py` 至少覆盖 10 类

| 效果 | `parse_effect` 断言 | `apply_effect` 断言 |
|---|---|---|
| 单体伤害 `scope="target"` | `damage`/`scope` | 目标随从掉血；目标为英雄时 `hero_hp` 下降（含法伤） |
| `enemy_minions` | `damage`/`scope` | 对方全体随从掉血，我方不动 |
| `all_minions` | `aoe is True` | 双方随从都掉血 |
| `enemy_hero` | `scope` | 只扣英雄 |
| `random_enemy` | `scope` | 有随从打随从、没随从打脸 |
| `destroy` | `destroy is True` | 目标死亡、`alive is False` |
| `destroy` + `all_minions` + `min_atk` | `min_atk` | 攻击力低于门槛的存活 |
| `heal` | `heal` 数值 | 友方随从回血；目标为英雄时 `hero_hp` 增加且不超过 30 |
| `armor` | `armor` 数值 | `armor` 增加 |
| `freeze` | `freeze is True` | 目标 `frozen is True` |
| `summon` | `summon_atk/summon_hp/summon_count` | 场上多出对应数量随从 |
| `buff` | `buff_atk/buff_hp` | 目标属性增加 |
| `draw` | `draw` 数值 | `hand` 增加、`deck` 减少；空牌库时进疲劳 |
| `set_hp` | `set_hp` 数值 | 双方随从血量被压到该值 |

外加两条：

1. **`known=False` 的牌**：`Effect(known=False)` 的默认值不得让 `apply_effect` 崩（认不出的牌会被建议引擎降权，这条是防御）。
2. **僵尸权重**：构造一个「对手总攻 ≥ 我方血量 + 护甲」的局面，断言
   `evaluate(b, {"lethal_bonus": 0}, perspective=0) == evaluate(b, {"lethal_bonus": 100}, perspective=0)`（修复前两者相差 42000，因为它真的在乘这个不存在的权重）；再加一条普通局面（不触发防守阶跃）证明分母之外的行为没变。以及 `len(model.DEFAULT_WEIGHTS) == 7`、键集合不变。
