### 3.2 `AGENTS.md`

1. 「跑起来」小节里的 `python -m unittest discover -s tests   # 123 个用例` 改成实际数字（或直接去掉数字只留命令——这更耐久，二选一并在交接物里说明选了哪种）。
2. 在「坑（都是真踩过的）」末尾追加下面 9 条（**合并去重后**；每条 2–4 行，格式模仿现有坑：加粗小标题 + 现象 + 为什么）：

   a. `reset()` 漏一个字段，第二局才开始错（来源 01）：
   > **`reset()` 里漏一个字段，第二局才开始错**。`_id_by_hand_done` 曾经只在 `_fix_our_id_by_name()` 里置 True、`reset()` 没清零，于是同一进程第二局起「按可见手牌翻面」永远提前 return，而第一次启动永远是对的。给 `GameState` 加任何「本局内有效」的字段，都要在 `reset()` 里给初值。

   b. `apply()` 里同一个 `elif kind` 只能有一个（来源 01）：
   > **`apply()` 里同一个 `elif kind == "..."` 只能有一个**。`block_start` 曾经出现两次，后一个分支（`_bind_by_action`）永远不可达：名字绑定少一条路，没有任何报错。改完 grep 一遍 `kind ==`。

   c. 双方抽牌分开记（来源 01）：
   > **双方抽牌要分开记**。日志里 `NUM_CARDS_DRAWN_THIS_TURN` 双方都有；只记我方会让「对手牌库数 = 30 − 我方抽牌数」，而预判拿它当分母算概率。

   d. 斩杀估算与 `apply_action` 同口径（来源 02）：
   > **斩杀估算必须和 `apply_action` 同一口径**：场上法伤、英雄自身攻击、武器风怒/耐久、英雄技能，两处只要有一处漏算，就会「理论能斩却判不能」。改其中一处时先 grep 另一处（`max_face_damage` / `apply_action` / `model.apply_effect`）。

   e. 一个对象别建两遍 + `or` 会把 0 当未知（来源 02，合并成一条）：
   > **一个对象不要建两遍，`x or 默认值` 会把合法的 0 当成未知**。`board_from_state` 里 `me.weapon` 曾被构造两次，后一次把 `durability` 覆盖成 1、风怒丢掉；牌库 0 张（疲劳）被 `or` 当成「没数据」，模拟里凭空多 30 张牌。区分「读到 0」和「读不到」要用 `is None`。

   f. `Effect` 三处一致 + `evaluate` 权重键必须存在（来源 03，合并成一条）：
   > **`Effect` 三处（字段 / `parse_effect` / `apply_effect`）必须一起改；`evaluate()` 读的每个权重键都必须在 `DEFAULT_WEIGHTS` 里**。前者漏一处只会静默少结算，后者漏了就是恒取默认值（`lethal_bonus` 曾恒为 1，看起来可调实际调不了）。现在有模型层的表驱动效果用例兜底（03 号任务新增）。

   g. 学习命令要说出「跳过了什么」（来源 04）：
   > **「修正 0 个」必须有原因**。学习命令只打印结果数字时，「跑成功但什么都没改」和「改了很多」看起来一样；schema 1 的 174 行就这样静默错过一个月。可观测性改动不许改口径（`prior_base` 顺序、混合权重、幂等性）。

   h. 聚类平均连接（来源 05）：
   > **单链聚类会串味**。A~B、B~C 但 A≁C 时，单链会把三套牌并成一簇，签名只剩中间那套的牌。修的顺序是「单链 → 平均连接 → 签名加局数下限 → 超 30 张报警」；**改完必须 `meta rebuild --dry-run` 看原型张数**，连接方式一改「哪些牌进模板」就变了。

   i. 写 JSONL 必须有人读 + UI 别丢分差（来源 06，合并成一条）：
   > **写进 JSONL 的功能必须有人读**。`advice_feedback.jsonl` 曾经只写不读，重启就「消失」；加落盘时同时写读取方，并给「文件不存在/坏行」一条空结果路径。**引擎返回的置信度信号别在 UI 层丢掉**（`pick_choice` 的「与第二名分差」曾被调用方用 `_` 接住）。

3. **措辞必须与代码现状一致**：条目 h 里「改完必须 dry-run」是规则；但如果 05 号任务还没执行，**不要**在 AGENTS 里写「已改平均连接」——先看 `meta` 模块源码里的聚类判据是不是 `max(_jaccard(...))`，是就写「当前仍是单链，修的顺序是…」，不是才写「已改平均连接」。同理其他条目不要写「已修复 X」，只写规则/现象。
