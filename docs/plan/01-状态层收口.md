# 01 状态层收口：局间隔离、回合口径、双方牌库

> 优先级：P0（修正确性，先做）
> 规模：单模块（`hsai/state.py`），一个 AI 独立可完成
> 前置阅读：`docs/plan/00-现状.md` §3.1、§3.2、§3.3、§3.7、§5.15、§6
> 基线：HEAD `3177f60` + 工作区改动；全量测试 `Ran 160 tests … OK`（2026-11-05 实测）

## 1. 目标

让 `GameState` 在「同一进程连打两局」「日志缺 `CURRENT_PLAYER`」「对手也在抽牌」三种真实场景下给出正确状态，并清掉 `state.py` 里 5 处从未被读取的字段与 1 个不可达分支。

可验收：新增 `tests/test_state_reset.py` 全绿；全量测试 ≥160 且 OK；`snapshot()["opp"]["deck_count"]` 不再等于「30 − 我方抽牌数」。

## 2. 背景

来自 `00-现状.md` 的原始记录：

- **§3.1 / §3.7**：`_id_by_hand_done` 只在 `_fix_our_id_by_name()` 里被置 True（`state.py:687,691`），**`reset()` 没有清零**。后果：同一进程从第二局起，「按可见手牌翻面」的兜底永远提前 return，只剩「首个可见手牌锁定」一条路；而第一次启动永远是对的，极难复现。
- **§5.15 / §6**：`apply()` 里有 **两个** `elif kind == "block_start"`（`state.py:288-289` 与 `292-298`），第二个不可达，里面的 `_bind_by_action()` 从来没执行过 —— 名字绑定少了一条路，而且没有任何报错。
- **§3.3**：`_side()` 对**双方**都用 `30 - our_drawn` 算牌库（`state.py:1037-1038`），所以「对手牌库数 = 30 − 我抽了几张」。预判把 `opp.deck_count` 当分母用（`advisor.py:431`），错值会一路传到 AOE/单解概率。
- **§3.2**：`snapshot()` 仍直接比 `turn_owner`（`state.py:1205`），`summary()` 同理（`1221`）；而日志里 `turn_owner` 经常是 `None`，advisor 早已改用 `effective_turn_owner()`（`advisor.py:318-319`）。两条入口口径不一致。
- **§6 僵尸字段**：`cthun_by_source` 在 `reset()` 里赋值两次（`166`、`217`）、`turn_events` 只写不读（`232`、`493`、`782`）、`our_hand_played` 只写不读（`189`、`793`）、`_draw_tag_turn`（`221`）和 `_first_player_id`（`237`）只在 `reset()` 赋值。`_last_attack_key`（`273-274`）是动态属性，`reset()` 也没清。

### 3.1 `reset()`（`state.py:164-241`）

- 补 `self._id_by_hand_done = False`、`self._last_attack_key = None`。
- 删除重复赋值：`cthun_by_source` / `_choice_source` 现在各赋值两次（`166-167` 与 `217-218`），只留一份（语义等价的空容器）。
- 删除从未被读取的字段初始化：`turn_events`（`232`）、`our_hand_played`（`189`）、`_draw_tag_turn`（`221`）、`_first_player_id`（`237`），并删掉它们唯一的写入点（`493`、`782`、`793`）。
- 新增 `self.opp_drawn: int = 0`（见 3.3）。

### 3.2 `apply()` / `_on_block_start()`（`state.py:267-310`、`885-895`）

- 删掉第二个 `elif kind == "block_start"`（`292-298`），把「用 `ref.controller` 反推名字」的逻辑并进 `_on_block_start()`：
  ```python
  ctrl = (ev.data.get("ref") or {}).get("controller")
  if ctrl in (1, 2):
      self._bind_by_action(int(ctrl))
  ```
- 改完 `grep -n 'elif kind == "block_start"' hsai/state.py` 必须只有 1 处（`apply()` 开头还有一条 `if kind == "block_start" and ...ATTACK` 的特判，它不是 `elif`，不用动）。

### 3.3 双方抽牌分开记（`state.py:536-549`、`988-1043`）

- `_on_tag_change()` 的 `NUM_CARDS_DRAWN_THIS_TURN` 分支：保留「每回合归零、按段内最大值累加」的算法，但**按玩家分桶**：
  - 我们的玩家实体（`e.controller == self.our_id` 或 `e.id == self.player_ids.get(self.our_id)`）→ 累加 `self.our_drawn`（字段名不变，`advisor.py:339` 在读它）；
  - 其余玩家实体 → 累加新增的 `self.opp_drawn`；
  - `e.controller` 拿不到时跳过（不猜）。
- `_side()`（`1038`）：`s.deck_count = max(0, 30 - (self.our_drawn if pid == self.our_id else self.opp_drawn))`。
  我方仍然只是「30 − 抽牌」的兜底，advisor 会用登记卡组张数覆盖（`advisor.py:308-311,338-340`），本任务不要动那个覆盖。
- 缺省值保持 30：`opp_drawn` 为 0 时对手牌库显示 30。

### 3.4 `snapshot()` / `summary()`（`state.py:1201-1224`）

- `snapshot()["is_our_turn"]` 改为 `self.effective_turn_owner() == self.our_id`；`snapshot()` 开头补一次 `self._fix_our_id_by_name()`（`sides()` 会调、`snapshot()` 现在不会），保证视图与 advisor 看到同一套身份。
- `summary()` 的「我方/对方回合」也改用 `effective_turn_owner()`。

### 3.5 不要做的

- 不要动 `Side.as_dict()`（墓地透出在下一批，见索引「本批不做」）。
- 不要动 `effective_turn_owner()` 的推断规则、`can_attack()`、克苏恩事件层（`note_cthun_choice`/`cthun_view`）。
- 不要动 `_side()` 里其他字段、`_card_view()` 的任何键。
