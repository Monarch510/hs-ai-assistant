## 1. 目标

让引擎「看到的局面」和「算出来的斩杀」都自洽：`max_face_damage()` 把场上法伤、英雄自身攻击、武器风怒/可用次数算进去（与 `apply_action` 同口径）；`board_from_state()` 只构造一次武器（不丢耐久/风怒）；`score_choice()` 第 6 层不再恒为 False。

可验收：新增 `tests/test_lethal_complete.py`、`tests/test_choice_score.py` 全绿；全量测试 OK；`tests/test_advice.py`、`tests/test_policy_rules.py` 未修改且通过（它们的 `damage == 10` / 嘲讽不吃溢出的断言必须仍然成立）。

## 2. 背景

- **00 §2.3 斩杀缺口**：`max_face_damage()`（`policy.py:572-633`）只算一次武器攻击、不含英雄自身 `hero_atk`、不含场上法伤 `spell_damage`，也不含英雄风怒的第二下 —— 这些都会让斩杀被低估。对照 `apply_action`：法术打脸会加法伤（`policy.py:514-516`），`model.apply_effect` 的所有伤害分支也加法伤（`model.py:608-631`）。**同一个伤害存在两套算法**，正是 00 §5.14 说的坑。
- **00 §2.5 打分缺陷**：`score_choice()` 第 6 层写成
  `if effect.damage or effect.destroy or effect.taunt if hasattr(effect, "taunt") else False:`（`policy.py:1104`）。条件表达式优先级使整句等价于「`Effect` 有没有 `taunt` 属性」，而 `Effect` 没有这个字段（`model.py:91-118`），所以这一层**恒为 False**，快攻对局的解场/回血加分从未生效。
- **00 §3.5 英雄攻击**：`advisor.board_from_state()` 已经把 `me.hero_atk`（`advisor.py:223-228`）和 `me.hero_attacks_left`（`:229-236`）算好了，只是斩杀估算没用它们。
- **武器被建两遍**（00 未收录，属本任务顺带修复的实现缺陷，先在此登记）：`board_from_state()` 在 `advisor.py:170-174` 建了一次 `me.weapon`（`hp` 取 `durability`），又在 `:241-243` 建了第二次并把 `hp` 写死成 1；第二次覆盖第一次，`evaluate()` 的武器价值就按 1 点耐久算了。而且**两处都没设 `windfury`**，武器风怒在 `Board` 里根本不存在。这就是 00 §5.14「同一个数别留两套算法」的实例。
- **00 §6 僵尸读取**：`board_from_state()` 的 `me.deck` / `them.deck` 用 `deck_count or max(0, 30 - ...)`（`advisor.py:218-219`）。`deck_count=0`（疲劳期）是**合法值**，被 `or` 当成了「没有数据」，模拟里会凭空多出 30 张牌。

### 3.1 `hsai/policy.py` —— `max_face_damage()`（572-633）

1. **攻击段**（579-588）：把「随从攻击 + 武器」扩展成「随从攻击 + 英雄/武器攻击」。
   - 英雄攻击力：`max(me.hero_atk, me.weapon.atk if me.weapon and (me.weapon.hp or 0) > 0 else 0)`。
     **不要**把 `me.hero_atk` 和 `me.weapon.atk` 各算一次（有武器时两者通常相等，会翻倍）。
   - 次数：`me.hero_attacks_left`（0 表示本回合已经打过，**不能**当成未知按 1 次算；风怒时它已经是 2）。用 `min(2, me.hero_attacks_left)` 段。
   - 现有测试建的 `SideState` 没有设 `hero_atk` / `hero_attacks_left`（默认 0），所以这条改动不能凭空加伤害——这是保证 `test_advice.test_lethal_detected` 仍等于 10 的关键。
2. **法术段**（600-613）：每张打脸法术的伤害加上 `bonus = sum(u.spell_damage for u in me.board if u.alive)`，与 `apply_action` / `model.apply_effect` 一致。`face_spells` 的返回内容保持 `[名字...]` 不变。
3. **英雄技能**（615-619）：保持现状（`me.hero_power_used` 目前永远读不到，见 00 §3.5；本任务不改 state/advisor 的读取路径）。
4. 返回字典的键名一个都不要改（`attack/taunt_block/spell/hero_power/damage/need/lethal/has_taunt/face_spells`），UI、AI、`plan_turn` 都在用。

### 3.2 `hsai/policy.py` —— `score_choice()`（1102-1112）

把第 6 层条件改成可读、不依赖 `hasattr` 的判断，例如：

```python
if opp_fast:
    if effect.known and (effect.damage or effect.destroy):
        score += 0.8
    if effect.heal or effect.armor:
        score += 0.8
```

其余各层数值与顺序不许动（00 §2.2 的评分口径不在本任务调参范围）。

**已知限制，不要在本任务消除**：`pick_choice()` 的 `opp_fast` 在生产代码里没有调用方（唯一的调用点 `ui.py:736-739` 归属 06 号任务）。**本批统一口径：只修条件表达式本身，`opp_fast` 的生产接线放到下一批单独做**（现在没有可靠的「对手快攻」判断来源，AGENTS：读不到就别猜）。06 号任务也不要接它。

### 3.3 `hsai/advisor.py` —— `board_from_state()`（139-249）

1. **武器只建一次**：删掉 `170-174` 与 `241-243` 中的一处，合并成一段，保留：
   - `atk` 来自视图；
   - `hp = durability`（不是 1）；
   - `windfury = card.has("WINDFURY")`（从 `st.cards.get(id)` 取卡面）；
   - `weapon_attacks_left` 仍在合并后按 `st.can_attack(hero)` + 风怒算（逻辑不动）。
2. **牌库 0 张不再被当成未知**（`218-219`）：去掉 `or max(0, 30 - ...)` 兜底，`deck_count=0` 就补 0 张占位牌。改完 `30 - 手牌 - 场面` 的兜底只用于「拿不到值」的场景，不再覆盖合法的 0。
3. **英雄技能已用状态**（`238-240`）：`hp_view.get("used")` 读一个不存在的键（00 §6）。本任务不修数据来源，只在该行加一条一行注释：
   `# shortcut: 日志里没有可靠的「英雄技能已用」标记，这里恒 False，等拿到日志样本再接（见 00-现状 §3.5）`
   行为保持不变，不要写新猜测。

**明确不做**：不改 `_predict()` 里的 `opp.deck_count` 兜底（那是预判口径，00 §3.3 修在 01 号任务里）、不改学习记录部分（`_record_result`/`_finish_game`/`_collect_issues`）、不改 `_advice()` 的选路逻辑。
